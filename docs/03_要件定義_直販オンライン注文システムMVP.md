# MVP要件定義書：直販オンライン注文システム（仮称：オーダーマイスター）

- 作成日: 2026-07-14
- ステータス: ドラフト（社内レビュー前）
- ベンチマーク: [Owner.com](https://www.owner.com/)（米国、$499/月、ARR $80.5M・前年比+137%、評価額$1B）
- 位置づけ: 調査レポート第2弾の候補A（直販売上エンジン）の中核を「注文システム」に絞ってMVP化し、Phase 1に前倒し

---

## 1. 商品コンセプト

**「ポータルに払っている手数料を、自分の店の売上に取り戻す」**

飲食店の自社サイトに、手数料ゼロのオンライン注文（テイクアウト・自店配達）を組み込み、
「今月の直販売上 ¥X／ポータルに払っていたら ¥Y だった手数料」を毎月円建てで見せるサブスクリプション。

### なぜ当社がやるか（WEB制作との相性）

1. **注文システムは「サイトの一部」** — 注文ページの入口は店のWEBサイト。サイト制作・保守を握っている当社が最短距離にいる
2. **集客資産が揃っている** — サイトマイスター（サイト生成）+ MEOエージェント（Googleマップ集客）+ SNS運用。「注文が入る状態」まで一気通貫で作れるのは制作会社だけ
3. **既存クライアントに即提案できる** — 新規開拓不要で飲食クライアントにアップセル
4. **解約されない構造** — 注文（売上）が毎日流れるシステムは、ホームページ保守と違い「止められない」

## 2. 背景：手数料の算数

### デリバリーポータルの手数料（2026年時点）

| チャネル | 手数料 |
|---|---|
| Uber Eats（配達代行） | **売上の35%** |
| Uber Eats（自社配達プラン） | 約15% |
| 出前館（配達代行） | **最大40%** + 決済手数料 約3.245% |
| **自社サイト直販（本商品）** | **月額固定 + 決済手数料約3.6%のみ** |

### 店舗の損益イメージ（デリバリー/テイクアウト月商30万円の店）

| 項目 | Uber Eats経由 | 直販（本商品・スタッフ配達） |
|---|---|---|
| 手数料/システム費 | ▲105,000円（35%） | ▲29,800円（月額）+ ▲10,800円（決済3.6%） |
| 配達コスト | ポータル負担 | スタッフ配達（近隣・アイドルタイム活用）or Uber Direct従量 |
| **店の手残り差** | — | **月 +5〜6万円改善**（配達人件費を見ても優位） |

- 月商が大きいほど削減額は比例して拡大（月商100万なら手数料35万 vs 月額+決済 約6.6万）
- **配達スタッフがいない店向け**: Uber Direct（配達代行API、1件ごとの距離別固定料金）を注文システムに連携すれば、35%の販売手数料を払わずに配達だけ外注できる（Phase 2）

出典: [Uber Eats手数料解説](https://business.aumo.jp/column/ubereats-commission-store) / [出前館手数料解説](https://goistech.co.jp/blog/demaecan-commission-guide/) / [Uber Direct導入ガイド](https://www.gourmet-partners.com/5743/) / [Uber Direct開発者向けドキュメント](https://developer.uber.com/docs/deliveries-jp/overview)

## 3. 競合と差別化

### 国内競合（モバイルオーダー/テイクアウト注文システム）

| サービス | 価格 | 特徴 |
|---|---|---|
| funfo | 月額無料〜（決済3.35%〜） | POS+モバイルオーダー、3,500店舗 |
| Camel Order | 非公開（要問合せ） | 注文サイト作成、POS連携、大手実績 |
| eEAT | 月額1万円〜 | Uber Direct連携済み |
| 汎用系（Square, STORES等） | 月額無料〜数千円 | ECの延長。飲食特化でない |

出典: [モバイルオーダー比較（funfo）](https://www.funfo.jp/index.php/25_9/) / [アスピック比較](https://www.aspicjapan.org/asu/article/17715) / [eEAT](https://service.eeat.jp/)

### 差別化の核心：「注文システム」を売らない。「直販売上の成長」を売る

注文システム単体は既にコモディティ（無料〜1万円）。Owner.comが$499/月を取れる理由は
**「集客（SEO/SNS/CRM）→ 注文 → リピート → 成果の金額表示」を一体で提供し、売上成長にコミットする**から。

当社の差別化要素：

1. **サイト+MEO+SNSとの統合** — 注文ページ単体でなく「注文が入る集客導線」ごと提供（競合の注文システム会社は集客ができない）
2. **円建て成果ダッシュボード** — 「直販売上¥X／ポータル手数料換算で¥Y節約」を毎月自動レポート（競合に無い）
3. **AIリピート促進** — 注文で得た顧客リスト（ポータルは顧客情報をくれない）にAIがLINEで再注文を促す（Phase 2、調査候補Bのエンジンをここに載せる）
4. **既存顧客基盤** — 飲食クライアントへのアップセルで CAC ほぼゼロ

## 4. ターゲット

### プライマリペルソナ
- 個人〜数店舗経営の飲食店（当社既存クライアント中心）
- Uber Eats/出前館に出店済みで手数料に不満がある、またはテイクアウト需要があるのに電話でしか受けられていない
- 店主のITリテラシーは低め。スマホ/タブレットは使える。LINEは日常利用

### 導入条件（MVP段階）
- テイクアウト需要が見込める業態（弁当・寿司・焼肉・カフェ・中華 等）
- 自店配達する場合は配達可能な近隣商圏とスタッフの余力があること

## 6. 成果ダッシュボード仕様（差別化の核）

店主が毎月見る画面/レポートに必ず載せる数字：

1. **今月の直販売上: ¥312,400**
2. **ポータル経由だったら払っていた手数料: ¥109,340（35%換算）**
3. **実際のコスト: 月額¥29,800 + 決済手数料¥11,246**
4. **→ 今月の節約額: ¥68,294**（前月比・累計も表示）
5. 注文件数 / 客単価 / 新規・リピート比率 / 蓄積された顧客リスト数

「本商品の月額は、節約額の中から払える」ことを毎月数字で証明する。
レポート様式はMEOエージェントの月次レポートとトーンを統一し、将来の商材横断ダッシュボードの第1画面とする。

## 7. システム構成（案）

| レイヤ | 技術 | 理由 |
|---|---|---|
| フロント（注文ページ/管理画面） | Next.js（Vercel） | サイトマイスターとの統合容易性、マルチテナントのサブドメイン運用 |
| バックエンド/DB | Supabase（PostgreSQL, Auth, Realtime） | 注文のリアルタイム通知、行レベルセキュリティでテナント分離、MVP開発速度 |
| 決済 | Stripe Connect（店舗ごとの直接受領） | 当社が資金を預からない構成にし資金決済法リスクを回避。PayPayはPhase 2 |
| 通知 | LINE Messaging API（店舗向け通知・顧客向け完了通知） | 日本のSMB/消費者の標準チャネル |
| AI | Claude API（メニュー説明文生成・レポートコメント生成） | 既存商材と共通基盤 |

### マルチテナント設計の要点
- 店舗ごとに `store.example.jp/{店舗slug}` または独自ドメインサブディレクトリ
- メニュー・注文・顧客データはテナントIDで分離（Supabase RLS）
- 決済はStripe Connectで**店舗のアカウントに直接入金**（当社は月額課金のみ。売上金を預からない）

## 9. パイロット計画とKPI

### パイロット（MVP検証・90日）
- 既存飲食クライアントから **3〜5店舗**（テイクアウト需要のある業態を優先）
- 無償〜半額で提供し、成果データ（節約額実績）を営業資料化する

### 成功基準（本開発GO判断）
| KPI | 目標 |
|---|---|
| 店舗あたり月間直販売上 | ¥150,000以上（3ヶ月目） |
| 「節約額 > 月額費」の達成店舗率 | 80%以上 |
| 注文者のリピート率 | 20%以上（90日） |
| 店主の継続意向 | 5店舗中4店舗以上が有償継続 |

## 10. リスクと対応

| リスク | 対応 |
|---|---|
| 注文システム自体のコモディティ化（無料競合） | 「集客+成果ダッシュボード+AIリピート」の統合で土俵を変える。単体機能では戦わない |
| 注文が入らない店では価値ゼロ → 即解約 | 導入条件を設ける(テイクアウト需要)。MEO/SNSとのセット販売で集客から作る。O3の利用低下検知でCS介入 |
| 資金決済法・特商法 | Stripe Connectで店舗直接受領(当社は資金を預からない)。特商法表記・キャンセルポリシーのテンプレートを店舗ごとに整備 |
| 食品関連の法規制 | 販売者は店舗であり当社はシステム提供者。利用規約で責任分界を明確化 |
| 配達品質(スタッフ配達の遅延等) | MVPでは近隣商圏に限定する設計(エリア半径のデフォルトを狭く)。Phase 2でUber Direct併用 |
| 既存POSとの二重管理の手間 | MVPは管理画面+LINE通知で完結する軽い運用。POS連携はLaterで検証後に判断 |

## 12. ロードマップ上の位置づけ（更新）

本商品を **Phase 1（MVP）に前倒し**し、調査時のロードマップを以下に更新する：

| Phase | 商材 | 備考 |
|---|---|---|
| **Phase 1（MVP）** | **直販オンライン注文システム（本書）** | WEB制作との相性・既存顧客へのアップセル・成果の即時可視化 |
| Phase 1 並行 | D. AI検索対策（LLMO）アドオン | 変更なし。MEO顧客に即販売 |

| Phase 2 | Uber Direct連携 | 配達スタッフのいない店に商圏拡大 |
| Phase 3 | 統合（日本版Owner.com完成） | サイト+MEO+注文+リピートAI+成果ダッシュボードの旗艦パッケージ |

> 候補B（掘り起こし）は消えるのではなく、**本商品が生む「店が自分で持てる顧客リスト」の上で動くリピート促進モジュール**として、より強い形で Phase 2 に組み込む。ポータルは顧客情報を店に渡さないため、「顧客リストが店の資産になる」こと自体が本商品の隠れた最重要価値であり、Bとの接続で完成する。
